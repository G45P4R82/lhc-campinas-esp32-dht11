ESP32 + DHT11

Do fio no sensor até a mensagem MQTT: uma apresentação passo a passo para montar, configurar, gravar e testar o sensor externo.

Dispositivo: iot-sensor-externo-lhc-001

Aula prática · 02

O que vamos fazer?

Medir

O DHT11 informa temperatura e umidade do ambiente.

Conectar

O ESP32 entra no Wi-Fi e conversa com um broker MQTT.

Publicar

As medições chegam a aplicações inscritas nos tópicos.

Testar

Usaremos o Mosquitto para consultar dados e enviar comandos.

Aula prática · 03

Materiais e pinos

Materiais

ESP32, DHT11, protoboard, jumpers, cabo USB e resistor de pull-up de 10 kOhm se o módulo não possuir um.

Ligação usada pelo código

DATA → GPIO5
VCC → VIN
GND → GND

Bibliotecas

DHT sensor library, Adafruit Unified Sensor e PubSubClient.

Importante: o código usa #define DHTPIN 5. A referência antiga que cita GPIO4 deve ser desconsiderada.

Aula prática · 05

Configure o secrets.h

Duplique secrets.example.h, renomeie para secrets.h e substitua os valores de exemplo pelas suas credenciais.

#define WIFI_SSID "NOME_DA_SUA_REDE"
#define WIFI_PASSWORD "SENHA_DO_WIFI"
#define MQTT_HOST "ENDERECO_DO_BROKER"
#define MQTT_PORT 1883
#define MQTT_USERNAME "SEU_USUARIO_MQTT"
#define MQTT_PASSWORD "SUA_SENHA_MQTT"

Segurança: secrets.h está no .gitignore. Não o publique. Use sempre placeholders em prints, apresentações e comandos compartilhados.

MQTT básico · 01/04

O que é MQTT?

MQTT é um protocolo leve de mensagens. Ele permite que dispositivos pequenos troquem informações sem precisar conhecer diretamente todos os outros dispositivos.

Leve

Mensagens pequenas e baixo consumo de rede.

Assíncrono

Quem publica não precisa esperar o receptor responder.

Ideal para IoT

Funciona bem em sensores, automação e redes instáveis.

MQTT básico · 02/04

Cliente, broker e tópico

Cliente

Qualquer programa conectado ao MQTT. Aqui, o ESP32 e o computador são clientes.

Broker

Servidor central que recebe mensagens e entrega aos clientes interessados.

Tópico

Endereço textual que organiza as mensagens, como sensores/.../ambiente.

O cliente pode fazer publish para enviar ou subscribe para receber.

MQTT básico · 03/04

Como uma mensagem viaja?

O cliente publica no broker, e o broker entrega a mensagem aos clientes inscritos no tópico.

ESP32
publish
→
Broker MQTT
recebe e roteia
→
Aplicação
subscribe
MQTT básico · 04/04

Por que separar canais?

Um tópico representa uma finalidade. Separar finalidades evita misturar leitura, comando e estado na mesma fila.

Organização

Cada mensagem tem um lugar previsível.

Permissões

É possível permitir publicar ou ler apenas determinados tópicos.

Consumo

Uma aplicação pode ler dados sem receber comandos.

Escala

Outros sensores podem usar a mesma estrutura com IDs diferentes.

MQTT neste projeto

Os quatro canais

1 · Ambiente

sensores/.../ambiente

O ESP32 publica temperatura, umidade e sensação térmica a cada 30 segundos.

2 · Resposta

sensores/.../resposta

Recebe o resultado de uma leitura solicitada pelo comando read.

3 · Comandos

comandos/.../cmd

O computador ou sistema envia instruções para o ESP32.

4 · Status

sensores/.../status

Informa estados de conexão, como {"status":"online"}.

Aula prática · 06

Instale e grave

  1. Instale Arduino IDE, suporte ESP32 e as três bibliotecas do projeto.
  2. Configure o secrets.h.
  3. Abra o arquivo lhc-campinas-esp32-dht11.ino.
  4. Selecione ESP32 Dev Module e a porta USB.
  5. Faça upload. Se necessário, segure BOOT, pressione e solte EN/RESET e depois solte BOOT.
  6. Abra o Monitor Serial em 115200 baud.
arduino-cli lib install "DHT sensor library" "Adafruit Unified Sensor" PubSubClient
arduino-cli compile --fqbn esp32:esp32:esp32 lhc-campinas-esp32-dht11
arduino-cli upload -p /dev/ttyUSB0 --fqbn esp32:esp32:esp32 lhc-campinas-esp32-dht11
Código · 01/05

Configurações e objetos

#define DHTPIN 5
#define DHTTYPE DHT11
#define PUBLISH_INTERVAL_MS 30000UL

DHT dht(DHTPIN, DHTTYPE);
WiFiClient wifiClient;
PubSubClient mqttClient(wifiClient);

As constantes definem o pino, o tipo do sensor e o intervalo. Os objetos representam o DHT11, a rede TCP e o cliente MQTT.

Código · 02/05

O que acontece no setup()?

  1. Configura o LED de status.
  2. Inicia a porta serial em 115200.
  3. Inicializa o DHT11 com dht.begin().
  4. Define endereço, porta e callback do MQTT.
  5. Força a primeira publicação logo após conectar.
Código · 03/05

O ciclo do loop()

connectWiFi();
connectMqtt();
mqttClient.loop();

if (millis() - lastPublish >= 30000) {
  publishReading(false);
}

O loop mantém as conexões, processa comandos recebidos e verifica sem bloquear o relógio se já chegou o momento da próxima leitura.

Código · 04/05

Wi-Fi e MQTT

connectWiFi()

Coloca o ESP32 em modo estação, conecta na rede e aguarda até receber um IP.

connectMqtt()

Tenta o broker a cada 5 segundos, assina o tópico de comandos e publica o status online.

Se alguma conexão cair, o loop tenta restabelecê-la.

Código · 05/05

Leitura, JSON e publicação

  1. dht.readHumidity() lê a umidade.
  2. dht.readTemperature() lê a temperatura.
  3. O código calcula a sensação térmica.
  4. snprintf() monta o payload JSON.
  5. mqttClient.publish() envia ao tópico ambiente ou resposta.
{"temperature_c":25.40,"humidity_percent":60.00,"sensor_status":"ok"}
Controle remoto

Comandos disponíveis

read

Solicita uma leitura imediata. A resposta é publicada no canal resposta.

restart

Publica um aviso e reinicia o ESP32. Use apenas quando realmente necessário.

O callback MQTT só aceita comandos recebidos no tópico comandos/.../cmd.

Teste prático

Consulte com Mosquitto

Substitua os placeholders pelas suas credenciais do secrets.h.

mosquitto_sub \
  -h MQTT_HOST -p MQTT_PORT \
  -u MQTT_USERNAME -P MQTT_PASSWORD \
  -t "sensores/iot-sensor-externo-lhc-001/#" -v

Esse comando acompanha ambiente, resposta e status.

mosquitto_pub \
  -h MQTT_HOST -p MQTT_PORT \
  -u MQTT_USERNAME -P MQTT_PASSWORD \
  -t "comandos/iot-sensor-externo-lhc-001/cmd" \
  -m "read"

Depois do read, procure uma mensagem no tópico resposta.
